CLAUDE.md 配置：3 条让 Token 消耗砍半的硬规则

把 CLAUDE.md 当作"合同"而不是"百科"

Alex Fraser 综合 12 仓库实战经验，给出 CLAUDE.md 三条立刻见效的硬规则——核心思想是 Claude 对 prompt 首尾内容权重最高，且文件越长越容易被忽略。

  1. 分层结构 · 首尾留给硬规则。顶部放"绝对不要做什么"的硬约束（删除测试、跳过 lint），中间放上下文规则，底部放参考资料。中间段落容易被模型"读到一半略过"。
  2. 300 行硬上限。超过这个长度，Claude 的遵守率会显著下降；与其堆叠不如拆成 docs/ 目录中的引用文件，让 Claude 按需 Read。
  3. 不写 Claude 已知的事情。"使用 TypeScript""遵守 PEP 8"这种通识浪费上下文；只写项目独有的约定（自定义 lint 规则、特殊命名空间、非典型架构）。

进阶招：维护一个 CORRECTIONS.md 作为"机构记忆"，每次纠正 Claude 后追加一条；下次启动时让 Claude 优先读这份文件，错误率会随时间收敛。

## 硬规则（绝对不可违反）
- 不修改 migrations/ 下任何文件，除非本任务明确要求
- 完成前必须跑通 `pnpm test` 与 `pnpm lint`，输出实际结果再宣布完成
- 单 PR 不超过 400 行 diff；超出则拆分
